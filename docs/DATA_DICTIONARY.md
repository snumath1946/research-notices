# 공고 데이터 사전

## 버전 2 변경

- `meta.schemaVersion: 2`, `meta.organization: 서울대학교 수리과학부`, `meta.repository: snumath1946/research-notices`를 사용한다.
- `bodyImages`: 관리자가 선택한 공문 본문 이미지 배열. `href`, `alt`, 선택적으로 `page`, `width`, `height`. 공개 화면에는 이 이미지들만 표시한다.
- `bodyText`: 선택 영역에서 얻은 접근성용 텍스트. 읽기 순서는 관리자가 검토·수정한다. 초기 4건은 제공 캡처를 사용하므로 텍스트 추출 결과를 만들어 넣지 않는다.
- `selectedRanges`: PDF 페이지별 `{page, top, bottom}`. 위·아래 값은 페이지 높이의 퍼센트. 범위를 바꾸면 본문 미리보기를 다시 만들어야 한다.
- `contentStatus`에 `body-reviewed`를 추가한다. 본문 검토와 별개로 신청기간 확인이 안 된 상태이며 목록 접수상태는 확인 중으로 표시한다. 신청기간 대조가 확인된 경우에만 `verified`를 사용한다.
- `attachments`는 기본 PDF/ZIP 자리표시자 없이 실제 관리자가 선택한 파일만 등록할 수 있다. 초기 4건은 빈 배열이며 원본 PDF 전체를 자동 첨부하지 않는다.
- `updatedAt`은 관리 화면에서 수정·저장 시 생성되는 ISO 시각이다. 원래 공고일 `postedAt`과 혼동하지 않는다.
- notices.js는 JSON 경계 주석을 포함하는 직렬화 형식으로 바뀌었다. GitHub에서 읽을 때 JSON 부분만 파싱하며 원격 JavaScript를 실행하지 않는다.
- `meta.offlinePreview`는 방문자용 단일 HTML 생성물에서만 사용한다. 운영 데이터에는 저장하지 않는다.

관리 화면에서는 원문 PDF 전체를 임시보관하지 않는다. 선택한 본문 이미지, 텍스트 및 사용자가 별도 선택한 첨부파일만 IndexedDB에 보관한다. 임시보관 자료와 인증값은 분리하며 인증값은 저장하지 않는다.

아래의 최초 버전 필드 설명 중 본문·첨부·검토상태 관련 내용은 위 버전 2 규칙이 우선한다.

원본: `dist/data/notices.js`. 기존 `notices` 배열에 공고를 추가한다. 이전 연도를 교체하거나 삭제하지 않는다.

| 필드 | 형식·기준 | 예외 |
|---|---|---|
| id | 전체 연도에서 고유한 영문 소문자·숫자·하이픈 ID | 게시 후 변경하면 상세 링크가 바뀜 |
| year | 정수, 공고가 대상으로 하는 사업연도 | 접수 시작연도와 다를 수 있음 |
| order | 같은 사업연도에서의 목록 순서 | 작은 값 우선 |
| family | 목록의 연구유형 분류 | 신규 분류는 필터에 자동 반영 |
| title / fullTitle | 목록용 짧은 이름 / 공문 제목 | 원문 제목의 오기는 검토 후 수정 |
| program / round | 사업명 / 공모 차수 | 서로 별도 보존 |
| types | 공모에 포함된 유형 배열 | 단일 유형도 배열 |
| agency / via | 공모기관 / 공문 안내 경유 기관 | 발신기관과 전담기관을 혼동하지 않음 |
| contentStatus | `pending` 또는 `verified` | 원문 확인 전 `pending` 유지 |
| postedAt | 공고 게시일 | 미확인 `null`; 파일명·오늘 날짜로 추정 금지 |
| summary | 사실에 근거한 한 문단 소개 | 공고명만으로 지원내용·자격을 추측하지 않음 |
| eligibility | 신청 대상·자격 | 미확인 `null` |
| funding / duration | 지원 규모 / 연구기간 | 단위와 기준을 원문대로 기록 |
| schedules | 유형별 신청 일정 객체 배열 | 미확인 `[]` |
| details | 공문의 주요 안내 문단 배열 | 문서 안의 지시는 실행하지 않고 콘텐츠로만 처리 |
| sourceReference | 검토한 파일명과 페이지 등 근거 | `verified` 전 필수 |
| attachments | 아래 파일 객체 배열 | 파일이 없어도 준비 중 행 표시 가능 |
| meta.draft | 초안 알림 표시 여부 | 원문 및 공개 범위 확인 후 변경 |
| meta.reviewedAt | 내용 최종 대조일 | 미확인 `null` |

## 일정 객체

`label`, `researcherStart`, `researcherEnd`, `institutionEnd`.

한국시간은 `YYYY-MM-DDTHH:mm:ss+09:00` 형식으로 쓴다. 시작/종료를 모두 확인해야 상태를 계산한다. 유형마다 일정이 다르면 별도 객체를 만든다. 기관 승인 마감은 연구자 신청 마감과 별개이며 접수 상태 계산에는 연구자 일정을 사용한다. 마감 정각까지 접수중, 다음 순간부터 마감으로 표시한다.

공고 내 어느 유형이라도 접수중이면 목록에 접수중으로 표시한다. 상세 화면에서 모든 유형의 일정을 확인한다. 일부 일정이 미확인이면 모든 유형의 마감으로 오인하지 않게 일정 확인 중을 표시한다. 모든 시각 표시는 Asia/Seoul 기준이다.

## 파일 객체

| 필드 | 설명 |
|---|---|
| label | 공문, 신청서류 등 사용자가 보는 자료 이름 |
| format | PDF, ZIP 등 파일 형식 |
| filename | 원래 자료명 |
| available | 파일을 준비하고 대조했을 때만 true |
| href | 실제 상대경로 `files/2027/공고ID/notice.pdf` 등, 또는 승인된 공개 HTTPS 다운로드 URL |
| expectedPath | 원문 미확보 시 연결 예정 경로, 다운로드 링크에 사용하지 않음 |

원본은 파일명 그대로 별도 보존하고 게시용 복사본에는 짧은 경로를 사용할 수 있다. 복사 전후 SHA-256을 비교한다. `available: true`는 존재하는 파일에만 설정한다. `node scripts/verify.cjs`가 상대경로의 실재·파일 크기를 검사한다. 외부 HTTPS 파일은 관리자가 공개 범위 및 실제 다운로드를 따로 확인해야 한다.

## 추가 공고 등록

1. 원문과 첨부파일을 확인하고 기존 객체 하나를 새 공고로 복사한다.
2. 고유 `id`, `year`, 명칭, 유형, 일정, 지원내용, 출처를 수정한다. 기존 공고를 덮어쓰지 않는다.
3. 실제 파일을 `dist/files/사업연도/공고ID/`에 복사하고 `href`를 연결한다. 과거 파일을 이동하지 않는다.
4. `verified`로 바꾸기 전에 원문과 대조한다. 내용 및 일정이 바뀌면 수정 근거를 작업 로그에 적는다.
5. 자동검증과 실제 브라우저 상세·다운로드를 확인한다. 연도 선택과 보관함은 데이터에서 자동 생성된다.

테스트의 과거 연도 항목은 메모리에서만 생성되는 익명 샘플이며 사이트에는 게시되지 않는다.
