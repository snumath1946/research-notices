# PDF 등록 및 지속 관리 기능

## 목표·입력·출력·제외
- 목표: 관리자가 PDF를 첨부하고 캡처와 같은 본문 범위만 검토해 공고로 등록한다. 별도 첨부파일을 직접 추가한다. 이전 연도는 보존한다.
- 입력: 기존 정적 사이트, 제공된 본문 캡처 4개, 사용자 지정 계정 snumath1946. 지정 Z: PDF는 재확인했으나 여전히 접근 거부.
- 출력: PDF 본문 범위 추천·조정, 미리보기·텍스트 검토, 로컬 초안 보관, 첨부파일 관리, GitHub 영구 저장, 업데이트 ZIP 내보내기.
- 제외: 이번 작업 중 원격 저장소 생성·실제 커밋·배포. 운영자 자격증명 생성·수집. AI/OCR 외부 전송.

## 책임
- Delegate: PDF 처리, 본문 범위 선택, 첨부관리, GitHub 저장 코드, 테스트, 기존 4건에 캡처 반영.
- Review: 본문 경계·표·날짜, 첨부파일, 외부 공개 가능 여부.
- Own: 저장소 공개범위·실제 게시 승인, 관리자 자격증명 관리.

## 순서·완료 기준
1. 기존 기능·GitHub 계정·원본 접근 확인.
2. 샘플 기준 테스트: 가~사 본문 경계, 본문 밖 제외, 스캔 PDF 수동 확인, 첨부 검증, 데이터 보존, 잘못된 계정 차단, 동시 수정 충돌 방지.
3. 기존 제공 PDF.js 5.6.205와 JSZip 3.10.1을 로컬 동봉. 라이선스·해시·감사 결과 기록. 새 패키지 설치 없음.
4. 관리자: PDF → 범위 검토·수정 → 첨부파일 → 미리보기 → 임시보관/업데이트 내보내기/GitHub 저장. 저장 전 명시적 확인.
5. GitHub: 소유자 snumath1946 고정, 저장소명 기본 research-notices(사용자 확인 대기). 인증값은 메모리에서만 사용. 기존 데이터를 원격 최신 상태와 병합, 하나의 커밋으로 파일과 데이터 저장, force:false.
6. 모델·PDF 실입력·모의 GitHub 프로토콜·브라우저 등록/재접속/다운로드·반응형 검증.

## 해석
- 캡처는 '가. 사업내용'부터 '사. 문의처'까지이며 본문 표·각주도 포함한다. 원문 PDF 전체는 자동 공개하지 않는다.
- 텍스트가 없는 스캔본이나 경계 탐지 실패 시 범위를 자동 게시하지 않는다. 관리자가 페이지 및 상하 범위를 직접 선택·확인한다.
- GitHub 연결이 없어도 초안과 업데이트 ZIP을 만들 수 있다. 로컬 임시보관을 다른 방문자에게 게시된 것으로 표시하지 않는다.
