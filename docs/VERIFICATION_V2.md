## 실패·수정·재검증 매니페스트

### 기능 선행 테스트
- 실패 증거: admin-core.js가 없는 상태에서 관리자 테스트가 MODULE_NOT_FOUND로 실패.
- 원인: 구현 전 정의한 실행 기준.
- 목표 수정: 본문 경계/등록 검증/직렬화/GitHub 저장을 구현.
- 예상 효과: 본문과 파일 등록을 실제 동작으로 검증.
- 회귀 위험: 기존 목록 및 자료 구조 변경.
- 재검증: 기존 10개와 신규 11개 모두 통과.
- 롤백: 이전 전달 소스를 별도 보관하거나 GitHub 도입 후 이전 커밋으로 되돌림. 과거 공고 데이터는 보존.

### Node의 PDF 실입력 테스트
- 실패 증거: 브라우저 빌드가 기대하는 Uint8Array.toHex가 Node에서 없어 실패.
- 원인: 브라우저와 Node 표준 API 지원 차이.
- 최소 수정: 테스트 파일에서만 Buffer 기반 표준 메서드를 보완. 사이트 코드는 바꾸지 않음.
- 재검증: 실제 한국어 2페이지 PDF 경계 검증 통과. Node에서 브라우저 빌드 사용 및 표준 폰트 경로에 대한 경고가 남지만 텍스트 검증은 통과. 실제 브라우저 PDF 처리에는 경고 없음.

### ZIP 다운로드 검증 한계
- 실패 증거: 자동 다운로드 이벤트, 명시적 다운로드 링크 이벤트, downloadMedia에서 각 시간 초과. UI에는 ZIP 생성 완료와 다운로드 링크가 표시됨.
- 추정 원인: 앱 내 브라우저의 Blob 다운로드/완료 이벤트 관측 제약. 원인은 확정하지 않음.
- 최소 수정: 준비된 ZIP의 명시적 다운로드 링크를 제공. 이미 압축된 파일은 STORE로 묶어 브라우저 처리 부담을 줄임.
- 재검증: ZIP 생성과 링크 표시 확인. 실제 다운로드 완료 관측은 세 차례 실패하여 중단함.
- 추가 증거: 브라우저와 같은 생성 함수를 Node에서 실행한 ZIP의 CRC, 공고 데이터, 첨부 바이트, 과거 공고 보존, 원문 제외 테스트 2개 통과.
- 선택지: 일반 Chrome/Edge에서 파일 저장 확인 또는 GitHub 저장 기능 사용. ZIP 생성 성공을 다운로드 완료로 보고하지 않음.

### 의존성 감사
- 기존 제공 PDF.js 5.6.205와 JSZip 3.10.1을 재사용. 설치·lockfile 생성 없음. dist/vendor/manifest.json으로 200개 동봉 파일의 SHA-256을 고정.
- npm 감사 API 요청은 TLS/인증 오류로 실패. 취약점이 없다고 판정하지 않았으며 신규 설치로 우회하지 않음.
- 공식 PDF.js 최신 릴리스 v6.5.438(2026-11-01)을 확인했으나 이번에는 기존 제공 버전을 사용. 운영 전 최신화/취약점 검토가 남음.

## 미실행·제한

- Z: 원문은 명령 실행 환경에서 접근 거부. 현재 배포용 공고 4건은 제공 캡처에 근거한다.
- 원격 GitHub 계정은 songh2만 연결됨. snumath1946 저장소 생성·커밋·Pages 배포를 실행하지 않음.
- GitHub 저장은 계정 확인, 원격 최신 목록 읽기, 단일 커밋/비강제 참조 갱신 및 충돌 처리를 모의 API로 검증. 실제 네트워크 쓰기 검증은 남음.
- PDF 본문 텍스트가 없으면 수동 범위 선택. OCR 자동 인식은 제공하지 않음.
- 단일 HTML은 방문자 확인용으로 본문 이미지를 포함하도록 생성. 관리자 모듈은 HTTP/HTTPS 환경이 필요.
